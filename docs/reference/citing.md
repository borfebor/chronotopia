# Citing Chronotopia

## The short version

Cite the software, and **say which version you used**. The numerical defaults
change between versions — which detrending methods exist, which period method is
selected first, how the entrainment window is handled — so "analysed with
Chronotopia" is not reproducible on its own. "Chronotopia v0.8.0" is.

The repository carries a [`CITATION.cff`](https://github.com/borfebor/chronotopia/blob/main/CITATION.cff)
file, so GitHub's *Cite this repository* button produces correctly formatted
BibTeX and APA entries.

!!! warning "Before the first release"

    `CITATION.cff` still has open items: the author list and ORCIDs need
    confirming, the repository has no `LICENSE` file yet, and there is no DOI.
    A Zenodo archive of a tagged GitHub release will mint one; do that before
    the manuscript goes out, and add `doi:` to the file.

## What to put in a methods section

The parts of a Chronotopia analysis a reader needs in order to repeat it:

| What to state | Example |
|---|---|
| Version | Chronotopia v0.8.0 |
| Preprocessing | starting timepoint 3 h; no smoothing; rolling-mean detrending; no normalisation |
| Entrainment | 2 cycles of 24 h, excluded from period estimation |
| Period method | Lomb-Scargle periodogram, 16–32 h search range |
| Rhythmicity | MetaCycle `meta2d`, Benjamini-Hochberg, q < 0.05 |
| Exclusions | wells A6 and D3 excluded (no signal) |

The app's exported control reference lists every setting with its tooltip, which
makes this easier to assemble accurately than reconstructing it from memory.

!!! tip "Report period differences, not just absolute values"

    As [Tutorial 2](../tutorials/long-series.md#step-6-estimate-the-period)
    shows on data with a known answer, three period methods on the same
    recording agree on the *comparison* between genotypes to within a few
    minutes, but disagree with each other by up to 0.7 h on the *absolute*
    number. Quote the method alongside any absolute period.

## Cite the methods underneath

Chronotopia is a front end over established algorithms. When you use one, cite
it — the original paper is the reference a reviewer will look for, not this app.

| Chronotopia option | Cite |
|---|---|
| `meta2d`, JTK, ARS, LS | Wu *et al.* 2016, *Bioinformatics* — MetaCycle |
| JTK_CYCLE | Hughes *et al.* 2010, *J Biol Rhythms* |
| ARSER | Yang & Su 2010, *Bioinformatics* |
| Lomb-Scargle | Glynn *et al.* 2006, *Bioinformatics*; implementation via `astropy.timeseries` |
| Wavelet Transform | Mönke *et al.* 2020 — pyBOAT |
| Savitzky-Golay smoothing | Savitzky & Golay 1964, *Anal Chem* |
| Benjamini-Hochberg FDR | Benjamini & Hochberg 1995, *J R Stat Soc B* |

The scientific Python stack underneath — NumPy, SciPy, pandas, statsmodels,
matplotlib, scikit-learn, Astropy — each has its own citation, and most journals
expect at least NumPy and SciPy to be credited.

## Citing the tutorial datasets

The two tutorial datasets are synthetic and generated from a fixed seed, so they
can be used as a shared reference case without any data-availability
complication. If you use them in a benchmark or a teaching context, point at the
generator rather than redistributing the CSVs:

> Synthetic datasets generated by `tutorials/make_tutorial_data.py` from
> Chronotopia v0.8.0 (seeds 20260804 and 20260805).

Every planted parameter is recorded in the `_truth.csv` files shipped alongside,
so a benchmark against them is checkable by anyone.
